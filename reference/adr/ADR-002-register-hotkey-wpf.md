# ADR-002: 採用 WPF 常駐 + RegisterHotKey (Alt+.)

## 背景
- `.lnk` 快捷鍵在符號鍵（.`/`）上存在保存與觸發限制，Console 模式無法可靠熱鍵啟動。
- 需求：全域熱鍵啟動翻譯、支援並行顯示結果、減少使用者啟動成本。

## 決策
- 新增 WPF 殼專案（`Rivet.WPF`），常駐背景、系統匣，單實例（Mutex）。
- 使用 Win32 `RegisterHotKey` 第 3 層全域熱鍵，固定組合 `Alt+.`，註冊失敗即記錄並退出，不提供改鍵（首版）。
- 主視窗預設隱藏；熱鍵顯示主窗單一「翻譯」按鈕，翻譯後開「譯文視窗」顯示結果，可並行多個譯文窗；預設不強制回寫剪貼簿，結果窗提供複製/可選回寫。
- 關閉或例外時必須 `UnregisterHotKey` 並釋放資源。

## 考慮的替代方案
- 繼續 Console + `.lnk` 快捷鍵：符號鍵不可靠，體驗差。
- AutoHotkey/啟動器（Ueli 等）轉接熱鍵：增加外部依賴，與內建熱鍵需求不符。
- Hook 型方案（低階鍵盤掛鉤）：優先權更高但衝突風險大，且需常駐；目前用 RegisterHotKey 即可。

## 影響
- 新增 WPF 專案、調整啟動入口/DI/發行流程；需常駐訊息迴圈。
- 單實例與並行翻譯策略：允許多譯文窗並行，但剪貼簿預設不回寫以避免互踩。
- 權限：若目標程式為系統管理員，Rivet 需同權限以確保熱鍵有效。

## 後續工作
- 完成 WPF 主程式、NotifyIcon、RegisterHotKey 註冊/解註冊、HwndSource Hook。
- 語言偵測與單鍵翻譯流程接入既有 Service/Infrastructure。
- 譯文視窗 UX：複製按鈕、可選回寫/條件回寫策略、焦點行為。
- 發行與文件更新：安裝啟動方式、熱鍵故障排除、權限指引。

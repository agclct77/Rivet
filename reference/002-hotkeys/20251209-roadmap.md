# Rivet 熱鍵與常駐化開發路線圖

## 決策概覽
- 採用 WPF 另起專案（建議 `Rivet.WPF`），現有 `Rivet.Console` 保留/後續可廢用。
- 固定全域熱鍵：`Alt+.`，使用 Win32 `RegisterHotKey`（第 3 層 Registered Global Hotkeys）。
- 單實例常駐：啟動一次後常駐背景與系統匣，攔截熱鍵；結束前 `UnregisterHotKey`。
- UI 策略：啟動後主視窗隱藏；熱鍵觸發時顯示主視窗「單一按鈕：翻譯」。執行翻譯後隱藏主視窗，開一個「譯文視窗」顯示結果（可同時存在多個）。

## 流程設計
- 啟動流程：
  - 程式啟動 → 建立 Mutex 防多開 → 完成 DI → 註冊 `Alt+.` → 建立 NotifyIcon → 隱藏主視窗。
- 熱鍵觸發：
  - 收到 `WM_HOTKEY` → 切回 UI 執行緒 → 顯示主視窗（單一按鈕：翻譯）。
- 翻譯指令（單一「翻譯」按鈕）：
  1) 偵測剪貼簿語言，決定翻譯方向（→繁中或 →英文）。
  2) 執行翻譯（讀剪貼簿 → 翻譯）。預設不強制回寫剪貼簿，結果顯示在新開的「譯文視窗」，內含複製按鈕/選項。
  3) 主視窗隱藏；可並行多個翻譯，每次開一個新的譯文視窗。
- 關閉流程：
  - 使用者從系統匣退出或程式結束 → `UnregisterHotKey` → Dispose NotifyIcon → 釋放 Mutex。

## 技術要點
- 熱鍵：`RegisterHotKey` 註冊 `Alt+.`，失敗時記錄錯誤並退出（不提供改鍵）。
- 訊息處理：不輪詢，依 Windows 訊息迴圈處理 `WM_HOTKEY`；WPF 用 `HwndSource.AddHook` 監聽。
- 單實例：Mutex 判斷；第二實例應退出或喚醒現有實例。
- UI 線程：所有視窗操作走 Dispatcher；主視窗以 Hide/Collapsed 常駐，避免 Close 退出應用；譯文視窗可獨立顯示並並行存在。
- 剪貼簿：並行翻譯時避免互踩，預設不強制回寫；結果窗提供「複製」或條件回寫選項。
- 通知：可用 NotifyIcon Balloon 或 Windows Toast；避免阻塞 UI。
- 權限：若目標應用以系統管理員權限執行，Rivet 需同權限以確保熱鍵有效。

## 風險與備忘
- 熱鍵被佔用：註冊會失敗 → 日誌 + 提示後退出。
- 並行翻譯：允許多譯文窗並行，但剪貼簿回寫需避免互踩（建議預設不回寫或採條件回寫/最新優先）。
- 子視窗焦點：開啟子窗時主窗可保持隱藏，避免焦點爭用；必要時 `Activate()` 提升。
- 清理：確保例外/關閉路徑皆解註冊熱鍵並釋放資源。

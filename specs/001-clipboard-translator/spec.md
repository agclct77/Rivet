# Feature Specification: 剪貼簿翻譯工具

**Feature Branch**: `001-clipboard-translator`  
**Created**: 2024-12-04  
**Status**: Draft  
**Input**: User description: "Rivet 工具箱：快捷鍵翻譯功能，按下 Alt+. 顯示選單，可將剪貼簿內容翻譯成繁體中文或英文"

## Clarifications

### Session 2024-12-04

- Q: 全域快捷鍵的實現方式？ → A: 使用 Windows 捷徑檔 (.lnk) 的「快速鍵」屬性，由使用者自行設定，快捷鍵改為 Ctrl+Alt+.
- Q: 翻譯完成後的通知方式？ → A: Console 視窗顯示訊息後延遲 0.5 秒自動結束
- Q: Google Cloud API 認證方式？ → A: 使用 %AppData%\Rivet\config.json 設定檔指定各服務的金鑰檔路徑，支援多服務擴充
- Q: 設定檔或金鑰檔不存在時的行為？ → A: 顯示錯誤訊息說明缺少設定檔或金鑰檔，並提示設定檔預期路徑
- Q: 使用者取消操作的方式？ → A: 按 Esc 鍵取消並關閉程式

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 將剪貼簿英文內容翻譯成繁體中文 (Priority: P1)

身為一位經常閱讀英文資料的使用者，我希望能夠快速將複製的英文內容翻譯成繁體中文，以便我能更快速地理解內容。

**Why this priority**: 這是核心功能的主要使用場景，英翻繁中是台灣使用者最常用的需求。

**Independent Test**: 複製一段英文文字，按下快捷鍵並按數字鍵 1 選擇翻譯成繁體中文，驗證剪貼簿已更新為翻譯後的繁體中文內容。

**Acceptance Scenarios**:

1. **Given** 剪貼簿中有英文純文字內容，**When** 使用者按下 Ctrl+Alt+. 開啟選單並按數字鍵 1 選擇「翻譯成繁體中文」，**Then** 系統將翻譯結果存入剪貼簿並通知使用者翻譯完成

---

### User Story 2 - 將剪貼簿繁體中文內容翻譯成英文 (Priority: P1)

身為一位需要撰寫英文文件的使用者，我希望能夠快速將複製的繁體中文內容翻譯成英文，以便我能更有效率地完成工作。

**Why this priority**: 這是核心功能的另一個主要使用場景，繁中翻英是常見的需求。

**Independent Test**: 複製一段繁體中文文字，按下快捷鍵並按數字鍵 2 選擇翻譯成英文，驗證剪貼簿已更新為翻譯後的英文內容。

**Acceptance Scenarios**:

1. **Given** 剪貼簿中有繁體中文純文字內容，**When** 使用者按下 Ctrl+Alt+. 開啟選單並按數字鍵 2 選擇「翻譯成英文」，**Then** 系統將翻譯結果存入剪貼簿並通知使用者翻譯完成

---

### User Story 3 - 透過快捷鍵開啟功能選單 (Priority: P1)

身為一位重視效率的使用者，我希望能透過全域快捷鍵快速開啟翻譯工具，並透過數字鍵快速選擇功能。

**Why this priority**: 快捷鍵是本工具的核心互動方式，決定了整體使用體驗。

**Independent Test**: 按下 Ctrl+Alt+.，驗證新的應用程式實例開啟並顯示功能選單。

**Acceptance Scenarios**:

1. **Given** 使用者在任何視窗工作，**When** 使用者按下 Ctrl+Alt+.，**Then** 系統開啟新的 Rivet 實例並顯示包含翻譯選項的功能選單
2. **Given** 功能選單已顯示，**When** 使用者按下數字鍵 1 或 2，**Then** 系統執行對應的翻譯功能
3. **Given** 翻譯功能執行完成，**When** 系統顯示完成通知，**Then** 應用程式實例結束

---

### User Story 4 - 處理非純文字剪貼簿內容 (Priority: P2)

身為一位使用者，當我嘗試翻譯非純文字內容時，我希望得到清楚的回饋訊息，讓我知道為何無法翻譯。

**Why this priority**: 錯誤處理是良好使用者體驗的重要部分，但屬於輔助功能。

**Independent Test**: 複製一張圖片，按下快捷鍵選擇翻譯，驗證系統顯示正確的錯誤訊息。

**Acceptance Scenarios**:

1. **Given** 剪貼簿中包含圖片（非 CF_UNICODETEXT 格式），**When** 使用者選擇翻譯功能，**Then** 系統顯示「無法翻譯非純文字」訊息

---

### User Story 5 - 處理空白剪貼簿 (Priority: P2)

身為一位使用者，當剪貼簿為空時選擇翻譯，我希望得到清楚的回饋訊息。

**Why this priority**: 錯誤處理是良好使用者體驗的重要部分，但屬於輔助功能。

**Independent Test**: 清空剪貼簿後，按下快捷鍵選擇翻譯，驗證系統顯示正確的錯誤訊息。

**Acceptance Scenarios**:

1. **Given** 剪貼簿內容為空（CF_UNICODETEXT 為空字串），**When** 使用者選擇翻譯功能，**Then** 系統顯示「剪貼簿內容為空無法翻譯」訊息

---

### Edge Cases

- 剪貼簿內容過長時如何處理？（**假設**：依翻譯服務限制處理，若超過限制則顯示錯誤訊息）
- 翻譯服務暫時無法連線時如何處理？（**假設**：顯示連線錯誤訊息並保留原始剪貼簿內容）
- 使用者快速連續按下快捷鍵時如何處理？（**假設**：每次都開啟新實例，各實例獨立運作）
- 選擇翻譯成繁中但剪貼簿內容已是繁中時如何處理？（**假設**：仍執行翻譯，由翻譯服務判斷並回傳結果）
- 使用者按下非 1、2 的數字鍵時如何處理？（**假設**：忽略無效輸入，等待有效選擇或按 Esc 取消）

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統必須支援透過 Windows 捷徑檔 (.lnk) 快速鍵 Ctrl+Alt+. 開啟新的應用程式實例並顯示功能選單
- **FR-002**: 功能選單必須顯示以下選項：[1] 翻譯成繁體中文、[2] 翻譯成英文，使用者可按對應數字鍵選擇，或按 Esc 鍵取消並關閉程式
- **FR-011**: 系統僅支援繁體中文與英文之間的雙向翻譯
- **FR-012**: 翻譯完成並通知使用者後，應用程式實例必須自動結束
- **FR-003**: 系統必須能夠讀取剪貼簿中的純文字內容（CF_UNICODETEXT 格式）
- **FR-004**: 系統必須能夠將翻譯結果寫入剪貼簿
- **FR-005**: 系統必須在翻譯完成後於 Console 視窗顯示訊息通知使用者結果已存入剪貼簿，並於 0.5 秒後自動結束程式
- **FR-006**: 當剪貼簿內容非 CF_UNICODETEXT 格式時，系統必須顯示「無法翻譯非純文字」訊息
- **FR-007**: 當剪貼簿 CF_UNICODETEXT 內容為空時，系統必須顯示「剪貼簿內容為空無法翻譯」訊息
- **FR-008**: 系統必須將剪貼簿內容以 Trace 層級記錄到日誌中
- **FR-009**: 系統必須將日誌輸出到 %AppData% 目錄下
- **FR-010**: 系統必須支援以責任鏈模式處理指令，以便未來擴充功能時不修改既有程式碼
- **FR-013**: 系統必須從 %AppData%\Rivet\config.json 設定檔讀取翻譯服務的金鑰檔路徑
- **FR-014**: 當設定檔不存在或金鑰檔路徑無效時，系統必須顯示錯誤訊息說明問題並提示設定檔預期路徑

### Key Entities

- **指令 (Command)**: 代表使用者從選單選擇的操作，包含指令識別碼與執行邏輯
- **翻譯請求 (Translation Request)**: 包含來源文字與目標語言
- **翻譯結果 (Translation Result)**: 包含翻譯後的文字或錯誤訊息
- **剪貼簿內容 (Clipboard Content)**: 代表從系統剪貼簿讀取的資料，包含格式類型與內容

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 使用者從按下快捷鍵到看見選單的時間不超過 500 毫秒
- **SC-002**: 一般長度文字（500 字元以內）的翻譯操作在 5 秒內完成
- **SC-003**: 使用者在首次使用時，能在 30 秒內成功完成一次翻譯操作
- **SC-004**: 所有錯誤情境都有對應的使用者友善訊息，不顯示技術性錯誤
- **SC-005**: 應用程式實例從啟動到結束的整體執行時間不超過 10 秒（一般情況）

## Assumptions

- 使用者的作業系統為 Windows，因為使用 Windows 特有的剪貼簿格式 CF_UNICODETEXT
- 使用者有可用的網路連線以存取翻譯服務
- Ctrl+Alt+. 快捷鍵透過 Windows 捷徑檔 (.lnk) 的「快速鍵」屬性設定，使用者需自行建立捷徑並設定快捷鍵
- 翻譯服務的金鑰檔路徑已正確設定於 %AppData%\Rivet\config.json
- 翻譯服務對單次請求的字元長度限制為合理範圍（通常 5000-10000 字元）
- 每次按下快捷鍵都會開啟新的應用程式實例，實例之間互不影響

## Constraints

- 必須使用 .NET 8 開發
- 前端初期使用 Console 介面，但架構需保留替換為 WPF 或其他 UI 框架的彈性
- 翻譯服務初期使用 Google Cloud Translation API，但架構需保留替換為其他翻譯服務的彈性
- 功能擴充採用責任鏈模式，確保符合開放封閉原則

## Out of Scope

- 翻譯歷史記錄功能
- 翻譯偏好設定（如保留特定術語不翻譯）
- 批次翻譯功能
- 離線翻譯功能
- 非 Windows 平台支援
- 繁體中文與英文以外的語言翻譯（如日文、簡體中文、韓文等）
- 常駐背景執行模式
